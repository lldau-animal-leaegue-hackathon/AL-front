# 적대적 코드리뷰 (Adversarial Code Review)

## 왜 중요한가

광역 스캔의 원시 발견은 오탐이 섞인다. 반박 검증 없이 보고하면 신뢰를 잃고,
**사전 제외 목록** 없이 돌리면 의도된 결정(호환성 때문에 일부러 구버전을 고정한 것 등)을
버그로 오탐한다. 결과 md는 "다른 모델·다른 세션이 md만 보고 수정을 완주"할 수 있어야 한다.

## 절차

### 1. 범위·기준 고정

대상 브랜치와 **기준 커밋 해시**를 기록한다(라인 번호의 유효 기준).
대상 파일 목록을 확정하고, 브랜치 diff(`main` 대비)로 회귀 추적 범위를 정한다.

### 2. 사전 제외 목록(KNOWN-INTENTIONAL) 주입

파인더·검증자 프롬프트에 의도된 결정을 명시해 오탐을 차단한다.
최신 목록은 `AGENTS.md`·`README.md`·직전 리뷰 md에서 갱신해 온다.
현재 기준은 `references/review-workflow.js`의 `KNOWN_INTENTIONAL` 상수를 쓴다.

### 3. 파인더 fan-out

도메인×렌즈로 파인더를 병렬 실행한다. 각 파인더는 담당 파일을 **전량 정독**하고
`git show`/`git diff`로 원본 대비 회귀를 추적한다.
출력 스키마: `file/line/title/severity/description/evidence`(구체 증거 필수).

**이 프로젝트에서 우선할 렌즈:**

- **서버/클라이언트 경계** — 서버 전용 값(`serverEnv`)이 클라이언트로 새는지,
  `"use client"`가 불필요하게 위로 올라가 번들이 부푸는지
- **데이터 정합성** — 점수 집계·아이템 사용·상점 구매처럼 되돌릴 수 없는 상태 변경
- **비동기 레이스** — out-of-order fetch, stale closure, SSE 재연결 중복
- **리소스 누수** — `EventSource`/타이머/구독의 cleanup 누락 (SSE를 쓰므로 특히 중요)
- **계약 위반** — 프롬프트 출력 스키마와 프론트 타입 불일치 (`ai-contract-check` 연계).
  LLM은 스키마를 보장하지 않으므로 런타임 검증 누락도 함께 본다
- **UX 계약** — 실패 시 상태, 빈값 시맨틱, 로딩 중 중복 제출

- **모델 핀**: 파인더·검증 에이전트는 항상 `model: 'fable'`로 스폰한다 —
  리뷰 판단 품질을 **세션 모델과 무관하게 상위 티어로 고정**하기 위함.
  종합·수정은 세션 모델이 이어받는다(리뷰=상위 티어, 실행=세션 모델의 비대칭 분업).

### 4. dedup → 발견별 적대 검증

파일+라인+주제로 중복 제거 후, 발견 1건당 독립 검증자 1개 이상을
**반박 기본 스탠스**("이건 버그가 아님을 증명하라")로 실행한다.
**구체 재현 시나리오**(입력→잘못된 출력)를 못 만들면 기각.
기각됐어도 컨벤션 위반이면 별도 부기한다.

### 5. 상위 건은 직접 재확인

확정 발견 중 제품 성분·루틴 안전(주의사항·성분 충돌)처럼 실해가 큰 건은 보고 전에 내가 직접 코드와
프롬프트 원문을 열어 재검증한다(`ai-contract-check` 연계).
멀티에이전트 판정을 그대로 전달하지 않는다.

### 6. 결과 md 작성

`references/review-md-template.md` 형식으로 `docs/plans/<YYYY-MM-DD>-<주제>/`에 저장한다
(plan-md 위치 규칙). 필수 요소: 기준 커밋 + "라인 밀리면 심볼 재탐색" 지침 / 사전 제외 목록 /
**이어받는 세션 작업 규칙**(커밋 정책·스킬 발동 지점·검증 수단·화면별 진입 경로 지도) /
**결정 필요 vs 즉시 착수 분리** / 항목별 체크박스(수정 시 커밋 해시 기록).

## 워크플로 예시

`references/review-workflow.js`를 복사·조정해 Workflow 도구로 실행한다.
최상단 `REVIEW_MODEL = 'fable'`이 파인더·검증 에이전트를 전원 Fable 5에 핀 고정한다.
**`FINDERS`(대상 도메인)와 `KNOWN_INTENTIONAL`(사전 제외)만 대상에 맞게 갱신하면 된다.**

> ⚠️ 이 프로젝트는 아직 도메인 코드가 적다. `FINDERS`를 그대로 쓰지 말고,
> 실행 전에 `src/` 실제 구조를 먼저 확인해 존재하는 범위로만 채운다.
> 없는 경로를 담당 범위로 주면 파인더가 빈손으로 돌아오고 토큰만 태운다.

> Fable 5 오케스트레이션까지 원하면 세션 자체를 `/model fable`로 바꿔야 한다
> (스킬은 세션 모델을 바꾸지 못함). 이 핀은 그 없이도 리뷰 에이전트만 상위 티어로 올리는 방법이다.

## 보고 형식

`원시 N → 확정 M(major a·minor b) / 반박 k` 통계를 먼저,
이어서 Major(데이터 정합성 기준)부터 항목별
`파일:라인 — 증상 — 실패 시나리오 — → 수정 방향`.

**수정 착수는 사용자 지시를 기다린다** (리뷰와 수정은 별개 승인).
