# Plan 문서 작성 (Plan MD)

## 왜 중요한가

긴 작업은 한 세션에 안 끝나거나 중간에 결정이 필요하다. plan 문서를 `docs/plans/`에 남겨두면
**세션이 끊겨도 이어서 작업**할 수 있고, 결정 사항이 기록으로 남는다.
작업이 여러 파일·여러 단계로 커 보이면, 코드를 건드리기 전에 먼저 plan을 만든다.

## 작성 위치

plan을 만들 때는 `docs/plans/` 안에 **생성 날짜를 앞에 붙인 대표 폴더**를 만들고 그 안에 md를 둔다:

```
docs/plans/<YYYY-MM-DD>-<주제>/<문서>.md
```

- 폴더명 = `생성날짜(YYYY-MM-DD)-주제` (예: `2026-08-20-score-realtime`). 날짜 prefix라 시간순 정렬·구분이 쉽다.
- 한 작업이 여러 문서로 갈라지면 그 폴더 안에 **하위 폴더**로 묶는다(예: `frontend/`, `backend-requests/`).
- 단일 md여도 같은 규칙(날짜 폴더 안)으로 둔다.
- **폴더/파일을 옮기면 md 간 상대 링크(`](...)`)를 새 경로로 갱신**해 깨진 링크가 없게 한다.

## 형식

ALWAYS 다음 구조를 사용한다:

```markdown
# <작업 제목>

## Context

왜 하는지, 배경.

## 결정 필요 사항

### Q1. <질문>

- 옵션 A: ... (장단점)
- 옵션 B: ... (장단점)
- 추천: <옵션 + 이유>

### Q2. ...

## 변경 대상 파일

| 파일 경로 | 작업 요약 |
| --------- | --------- |
| ...       | ...       |

## 구현 순서

- Step 1: ... (점진적으로 적용 가능하게)
- Step 2: ...

## 검증

- `npm run check` 통과 (타입 + 린트 + 포맷)
- `npm run build` 통과
- 서버/클라이언트 컴포넌트 경계 확인 — `"use client"`가 필요한 곳에만 붙었는지
- AI 응답을 다뤘다면 `ai-contract-check`로 프롬프트 출력 스키마 대조 완료
- dev 서버 UI 수동 확인 (진입 경로 명시)

## 비범위 (Out of Scope)

- 이번에 명시적으로 제외할 것
```

## 진행 규칙

- **결정 필요 사항(Q1~Qn)**이 있으면 옵션 A/B/C를 비교하고 추천을 제시한 뒤, 사용자 답변을 기다린다.
  답변을 받으면 문서 끝에 `## 결정 확정 (YYYY-MM-DD)` 섹션을 추가해 확정 내용을 기록한다.
- 구현이 진행되면 plan의 구현 순서에 진행 상태를 갱신해, 다음 세션이 이어받을 수 있게 한다.
- 작은 단발성 작업(파일 1~2개, 결정 불필요)에는 plan을 만들지 않는다 — 과한 절차는 오히려 방해다.

## 진행 상태 로그 문법

`## 진행 상태` 섹션의 각 항목은 다음 요소를 담아 **어느 세션이 이어받아도 맥락이 복원**되게 쓴다:

```
- [x] <항목명> — 완료 YYYY-MM-DD. <정량 수치(N파일 +a/−b, 1,522→360줄)>. <수행한 검증 결과 요약>.
  커밋: `<해시>`(주제) — 분할 커밋이면 도메인별로 나열. 사용자 결정은 날짜와 함께 인용
  ("사용자 결정(YYYY-MM-DD): 현행 유지"). **교훈은 굵게** 별도 기록.
```

- 보류/원복된 결정은 ~~취소선~~ + 결정 날짜로 남긴다(지우지 않는다 — 재논의 방지).
- 관련 문서(로드맵↔리뷰 결과↔BE 대기)는 상대 링크로 상호 참조한다.

## 외부 대기 게이팅

> ⚠️ ~~예전 이 절은 별도 백엔드 레포(`animal-league-04-back`) 명세를 기다리는 상황을 다뤘다.~~
> **이 프로젝트는 프론트와 백엔드를 전부 이 레포에서 만든다**(백엔드 = Next Route Handler).
> 그래서 "BE 대기"는 없어졌고, 대신 **내 손 밖에 있는 것**을 기다리는 경우가 남았다 —
> DB 서버 구축, 접속 정보, 외부 API 키, 디자인 확정 같은 것들이다.

내가 만들 수 없고 **남이 줘야 진행되는 항목**이 생기면:

- plan 상단에 `> ⏳ **<무엇> 대기(YYYY-MM-DD)** — <상황>` blockquote 배너를 달고,
  **대기 없이 진행 가능한 것**과 **와야 되는 것**을 구현 순서에서 **명시적으로 분리**한다.
  (예: `2026-08-18-server-storage` 는 스키마·인증·쿼리 골격을 앞에, 실제 연결·마이그레이션을 뒤에 뒀다.)
- 동결한 코드에는 본체 주석으로 사유를 남긴다("접속 정보 확정 대기로 현행 유지").
- "도착하면 확인할 것" 체크리스트를 미리 써 둔다. 각 항목에 **"빠지면 무엇이 깨지는지"** 를 부기한다
  — 도착 즉시 검증에 들어갈 수 있어야 한다.
- **가짜 기능 UI를 먼저 만들지 않는다.** 대비 주석과 하위호환 코드까지만 넣는다.
  화면에 그럴듯한 값을 채워 두면 나중에 그게 진짜인지 목업인지 아무도 구분 못 한다.
