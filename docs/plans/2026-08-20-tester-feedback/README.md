# 테스터 피드백 반영 (2026-08-20)

## Context

배포 후 받은 테스터 피드백을 배치 단위로 반영한다. 즉시 반영/후순위/보류를 구분해 기록한다.

## 배치 1 — 스캔

- [x] '검색' → 'AI 성분 검색' 개명 + 폼 하단 전폭 이동 (`ProductForm`)
- [x] 성분 못 찾음 빈 상태에 "성분표 촬영하기" 버튼 — 모달 닫고 바로 성분표 카메라
- [x] 등록 완료 모달: "루틴 다시 짜기"(주) + "다른 제품 등록하기"(보조) — X 와 기능 중복 해소
- [x] 촬영 오버레이 상시 다크 — inverse-surface 가 다크 모드에서 흰 화면이 되던 문제
- [ ] 성능(속도) — **실측**: 검색은 기본 모델 26.8초 vs haiku 16.4초·빈 결과 → 모델 전환 기각.
      남은 후보: 화해 검색 페이지를 LLM 없이 서버가 직접 파싱(37초→1~2초 예상).
      페이지 구조 조사(외부 fetch)가 필요해 사용자 승인 대기.
- 성능(적중률) — 이름만으로는 모델 기억 의존이 구조적 한계. 촬영 CTA + 공유 카탈로그
  성장으로 완화. 프롬프트 완화는 "지어내지 않는다" 원칙 위반이라 하지 않는다.

## 배치 2 — 루틴

- [x] 카드 '시작하기' 우측에 작은 '완료' 버튼 — 러너를 거치지 않고 실제 수행 기록
      (`appendRun`, 전 단계 완료)을 남긴다. 가짜 토글(Step 7 에서 삭제)과 다르다.
- [x] '고민 집중 케어' → '기타 루틴' 개명 — **표시만** 변경(`conditionLabel`).
      저장값 "고민 집중"은 기존 데이터 호환 때문에 유지.
- [x] 무료 상한 안내 — 루틴 2세트(기본+기타)가 구조적 상한. 목록 하단
      "루틴 더 만들기" 버튼 → Pro 업그레이드 안내(결제 흐름 없음, 표시만).
- [x] 생성 중 전면 차단 오버레이 — 스피너 대신 AI 작업 표시(auto_awesome 펄스 +
      경과 초 + 20초 이상 시 안내), 터치·스크롤 차단. 전용 라우트라 이탈 시 락 해제 안전.
- [x] 루틴 세트 삭제 — `DELETE /api/routines?condition=` 추가(없으면 전량 삭제, 기존 동작),
      죽은 코드였던 `clearRoutines` 를 `deleteRoutines(condition?)` 로 개편.
      확인 UI 는 ~~2탭(삭제→정말 삭제)~~ → **확인 모달**("정말 삭제하시겠습니까",
      공통 스크림 규칙)로 교체 — 사용자 요청 2026-08-20.
- [x] 수행 화면 순서 — 사용법 → 주의사항 → 팁 (기존: 팁 → 주의 → 사용법)
- [x] 루틴 이름에 고민 요약 — "블랙헤드 - 저녁 루틴" 형식. 프롬프트에 최상위
      `concern_summary`(2–8자) 추가(규칙 9), 라우트가 2–20자 밖이면 null 강등,
      이름은 요약 없이도 성립(폴백). `ai-contract-check` 실측표 갱신 + 실호출 검증.
      기존 저장 루틴 이름은 재생성 전까지 그대로다.

### 제안 — "수정 방법이 재생성뿐" 문제

전체 편집기는 과하다. 낮은 비용 순 3안:

1. **단계 삭제/순서 변경만** — 카드 펼침 화면에서 단계별 삭제·위/아래 이동.
   서버는 PUT(조건 단위 교체)을 그대로 쓰므로 라우트 변경 0. _추천: 수정 수요의
   대부분은 "이 단계 빼고 싶다"이다._
2. **부분 재생성** — 특정 단계만 "이 단계 다시 짜 줘"로 AI 재호출. 프롬프트 신설 필요.
3. **자유 편집 폼** — 단계명·시간·제품까지 편집. 검증·UX 비용이 가장 크다.
