## Context

현재 `/scan`은 **로컬 카탈로그 25종을 문자열로 거르는 검색** + **직접 입력 폼**이다.
카탈로그에 없는 제품은 이름을 손으로 치고 성분표 사진을 찍어야 등록된다.

사용자 요청의 핵심은 **"제품을 검색해서 찾는" 경험**이다. 그러려면 카탈로그 밖의 실제 제품
데이터가 필요한데, 외부 상품 API가 전부 막혀 있다(네이버 쇼핑 = 신규 발급 불가, 카카오 = 카탈로그 없음
— [products.ts](../../../src/app/scan/products.ts) 주석에 기록).

→ **화해(hwahae.co.kr)를 헤드리스 Claude의 웹 검색으로 읽는다.** 근거가 Claude의 기억이 아니라
실제 플랫폼 데이터라 이 레포가 지켜온 "지어내지 않는다" 원칙과 충돌하지 않는다.

### 선행 실측 (2026-08-18) — 설계를 바꾼 3가지

착수 전에 CLI를 실제로 돌려 확인했다. **추측으로 설계했으면 셋 다 틀렸을 것이다.**

#### ① 웹 도구는 동작한다 — 단, 화해는 절반만 열린다

| 대상                             | 결과                        |
| -------------------------------- | --------------------------- |
| `hwahae.co.kr/search?q=…`        | ✅ **열림** (마크다운 본문) |
| `hwahae.co.kr/goods/{id}` (성분) | ❌ **403** (AWS WAF)        |
| `incidecoder` 계열               | ✅ 성분 전체 반환           |
| `oliveyoung` · `skinsort`        | ❌ 403                      |

도구 이름은 **`WebSearch`·`WebFetch`** (바이너리 문자열에서 확인).

⚠️ **폴백은 구버전을 준다.** 같은 제품에 대해 화해는 24종(리뉴얼 포뮬러, 한글),
폴백은 21종(영문 INCI 구버전)을 반환했고 **3종은 화해 목록에 아예 없었다.**
스킨케어 앱에서 성분은 알레르기·자극과 직결되므로 이건 조용한 오답이다.

#### ② 속도는 프롬프트로 4.5배 줄었다

| 프롬프트                              | 소요              |
| ------------------------------------- | ----------------- |
| 자유 탐색(403 만나면 폴백 추적)       | 180–190초         |
| **상세 페이지 금지 + 폴백 금지 명시** | **37.0 / 41.5초** |

느렸던 원인은 웹 검색 자체가 아니라 **403을 만나 폴백을 15번 탐색한 것**이었다.
제약을 프롬프트에 못 박으면 검색 결과 목록만 3회 읽고 끝난다(WebFetch 3회, 4턴).

실제 제품이 나온다: 토리든 다이브인 저분자 히알루론산 토너, 라운드랩 1025 독도 토너 등.
⚠️ 단 **제품명에 판촉 문구가 섞인다** — `아쿠아 오아시스 토너 300ml 더블 기획 (+화장솜)`.
실제 목록을 읽고 있다는 증거이자, 표시 전에 다듬어야 한다는 뜻이다.

#### ③ ⛔ `--allowedTools`는 도구를 제한하지 않았다 (보안 결함, 이미 수정)

웹 검색과 무관하게 발견된 **기존 코드의 결함**이다. 세션이 직접 재현해 확인했다.

`~/.claude/settings.json`이 `defaultMode: "bypassPermissions"`라 권한 검사를 건너뛴다.
`--allowedTools`는 **권한 허용 목록**일 뿐이라 이 모드에서는 무력하다.
게다가 옛 코드는 목록이 비면 **플래그를 아예 안 붙여** 기본 도구 전체를 물려줬다.

| 인자                               | 실측 결과                                       |
| ---------------------------------- | ----------------------------------------------- |
| 플래그 없음 (**옛 runner**)        | ❌ `echo` 실행됨, `permission_denials: []`      |
| `--strict-mcp-config --tools ""`   | ✅ 도구 스키마 **0개** — 거부가 아니라 **부재** |
| `--strict-mcp-config --tools Read` | ✅ 이미지 읽기 정상(8.6초), 구독 인증 유지      |

해당 경로가 **3개 라우트 전부**였다 — `routine`·`warnings`는 도구를 안 주고,
`ingredients`도 **사진이 없으면** 빈 배열이 된다(가장 흔한 등록 방식).
셋 다 프롬프트에 사용자 입력이 그대로 들어간다.

`runner.ts:30` 주석은 _"비우면 도구 없이 실행한다"_ 라고 적혀 있었다 — **사실과 정반대**였고,
그래서 아무도 눈치채지 못했다. 틀린 주석은 없느니만 못하다.

→ **Step 0에서 수정 완료.** 회귀 없음을 실호출로 확인(`/api/ai/warnings` 36.2초, 주의사항 5개).

## 결정 필요 사항

### Q1. 프롬프트를 어디에 어떻게 보관할 것인가

사용자 요청은 _"env에 프롬프트를 저장해서 외부에서 프롬프트를 볼 수 없게"_ 다.

현재 프롬프트는 `src/lib/prompts/*.ts`에 있고 **이미 브라우저에는 안 나간다**(서버 전용,
빌드 검증 항목에도 있음). 따라서 실익은 **공개 레포에서 안 보이게** 하는 것이다.

⚠️ **충돌**: `ai-contract-check` 스킬은 _"프롬프트 원문이 정본"_ 이라 읽어서 매핑을 검증하는데,
AGENTS.md 보안 규칙은 **`.env` 파일을 읽지 말라**고 못박는다. 그대로 넣으면 다음 세션이
응답 매핑을 검증할 수 없다.

- **옵션 A: 지시문만 env, 스키마·규칙은 코드**
  `SCAN_SEARCH_PROMPT` 환경변수에 지시문 본문을 넣고, `src/lib/prompts/search.ts`에는
  출력 타입·런타임 검증·규칙 요약 주석을 남긴다.
  - 장점: 검증에 필요한 건 스키마지 지시문이 아니라 계약 검증이 계속 가능하다.
  - 단점: 프롬프트가 버전 관리를 벗어나 변경 이력이 안 남는다. 배포처마다 값을 넣어야 한다.
- **옵션 B: 프롬프트 파일을 gitignore**
  `src/lib/prompts/search.local.ts`를 만들고 `.gitignore`에 넣는다.
  `search.example.ts`(자리표시자)만 커밋한다.
  - 장점: 여러 줄 프롬프트를 코드로 다루기 쉽다(env는 개행·따옴표 이스케이프가 지저분하다).
    로컬에서는 읽을 수 있어 검증도 된다.
  - 단점: 파일이 없으면 빌드가 깨진다(example로 폴백 필요). "env에 저장"이라는 요청과 형태가 다르다.
- **옵션 C: 요청대로 전문을 env에**
  - 장점: 요청 그대로.
  - 단점: 여러 줄 프롬프트를 `.env`에 넣으려면 `\n` 이스케이프가 필요해 읽기·수정이 나쁘다.
    계약 검증이 막힌다.
- **추천: A.** 요청의 의도(공개 레포에 지시문 노출 금지)를 충족하면서 계약 검증을 살린다.
  ⚠️ 어느 쪽이든 **`NEXT_PUBLIC_` 접두사는 절대 금지** — 붙이면 브라우저 번들에 평문으로 들어간다.

### Q2. 카탈로그·화해에 없는 제품을 어떻게 등록하나

지금은 이름을 직접 입력해 등록할 수 있다. 화면이 "검색 → 후보 선택" 중심으로 바뀌면
**검색에 안 걸리는 제품의 등록 경로**를 정해야 한다.

- **옵션 A: 직접 입력을 남긴다** — 검색 결과 아래 "찾는 제품이 없나요? 직접 입력하기".
  기존 `ProductForm`을 그대로 두고 진입만 바꾼다.
  - 장점: 막다른 길이 없다. 이미 동작하는 코드다.
  - 단점: 화면에 경로가 둘이라 조금 복잡하다.
- **옵션 B: 사진 촬영으로만 유도** — 검색에 없으면 제품 사진을 찍게 한다.
  - 장점: 화면이 단순하다. 성분 근거도 확실해진다.
  - 단점: 사진을 못 찍는 상황(제품이 손에 없음)에서 막힌다.
- **추천: A.** 검색이 실패해도 사용자가 계속 진행할 수 있어야 한다.

### Q3. 상단 탭 상태를 URL에 반영할 것인가

- **옵션 A: `?tab=shelf` 쿼리** — 새로고침·뒤로가기·공유가 자연스럽다.
  `useSearchParams`가 필요해 그 조각이 클라이언트가 된다(이미 클라이언트다).
- **옵션 B: 컴포넌트 state** — 가장 단순. 새로고침하면 "스캔"으로 돌아간다.
- **추천: A.** 선반 탭은 프로필에서 옮겨 오는 **독립적으로 도달할 화면**이라
  주소가 없으면 링크를 걸 수 없다(예: 등록 완료 후 "선반에서 보기").

### ⚠️ 선행 실측 필요 — 결정이 아니라 확인

**성분명 검색(요청 1번)이 화해에서 되는가.** 제품명 검색은 실측했지만
"판테놀이 든 제품 찾아줘" 같은 질의가 화해 검색으로 성립하는지는 **확인하지 않았다.**
안 되면 성분 검색은 로컬 카탈로그의 `ingredients` 필드로 좁히거나, 토글 자체를 재검토해야 한다.
→ **Step 3 착수 전에 1회 측정한다.**

## 검증

- `npm run check` 통과 (타입 + 린트 + 포맷)
- `npm run build` 통과 — **신규 라우트 2개**라 `next typegen`이 먼저 돌아야 한다
- **서버/클라이언트 경계** — 탭·검색은 클라이언트, `page.tsx`는 서버 유지.
  `src/lib/prompts/*`·`serverEnv`가 클라이언트로 import되지 않았는지 grep.
  빌드 후 `.next/static`에서 **프롬프트 문자열이 검색되지 않아야** 한다.
- **`ai-contract-check` 필수** — 신규 엔드포인트 2개. 프롬프트 출력 스키마 대조 + 런타임 검증.
- **웹 도구 전용 확인**
  - 트랜스크립트에 **검색 결과 본문이 100KB 이상 쌓인다**(실측) → `cleanupSession: true` 필수
  - `--tools`에 `WebSearch,WebFetch`만 들어갔는지, 셸이 실제로 부재인지
- **다크 모드** — 신규 UI에 hex 하드코딩 0, 배경이 `--X-container`면 전경은 `--on-X-container`.
  아이콘·hover는 텍스트 스윕에 안 걸리므로 별도 확인(직전 작업에서 이 둘로 3건을 놓쳤다).
- **수동 확인 (dev 서버)**
  1. `/scan` → 탭 3개 전환. 새로고침 후 탭이 유지되는지(Q3 = A일 때)
  2. 검색 → 후보 목록. 제품명에 판촉 문구가 남지 않았는지
  3. 후보 선택 → 성분 조회 → **출처와 경고가 보이는지**
  4. 검색에 없는 제품 → 직접 입력 경로가 살아 있는지(Q2 = A일 때)
  5. 인기 제품 탭 → 선반에 담기
  6. **localStorage 비운 상태**로 전 탭 진입 — 크래시 없는지

## 비범위 (Out of Scope)

  뚫는 행위다. 폴백 출처 + 사진 촬영으로 간다.

  로딩으로 약 17k 캐시 토큰이 붙는 것을 실측했다. 구독으로 커버되고 지연에 큰 영향이 없어 미루지만,
  호출이 잦아지면 1순위 최적화 대상이다.
